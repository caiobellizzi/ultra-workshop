# Plan 04-06 — Make coder-specialist envelope deterministic

## Context

Plan 04-05 verified the async background-job flow works: `/build add a fibonacci(n) ...` fired correctly, the notification turn opened ~8 min later, and Hermes correctly branched on the captured exit code. **But the pipeline failed at the coder stage** with:

```
ValueError: [coder-specialist] No JSON object found.
```

Root cause: the coder-specialist SKILL.md instructs the LLM agent to (1) clone the sandbox, (2) create a branch, (3) run aider_runner.py, then (4) **assemble a Diff JSON envelope** and emit it as the final stdout. Step 4 is brittle — on this run the model returned a Python code block (`def fibonacci(n): ...`) instead of the JSON envelope. `workshop/orchestrator._extract_json` uses naive brace-matching and bailed because no `{...}` was present.

The fix is structural: **move envelope assembly from the LLM into a deterministic script** (mirroring how `workshop_build.py` already encapsulates the whole pipeline). The coder-specialist SKILL.md becomes a one-liner that runs `workshop_coder.py` and forwards stdout. This eliminates the failure mode entirely for the happy path.

Secondary fix: harden `_extract_json` to also accept ```json fenced blocks — defensive against the *other* specialists (triage, planner, reviewer) hitting the same class of bug.

## Design

### A. `hermes-skills/workshop_coder.py` (NEW — deterministic envelope producer)

A small Python script that performs the same five steps the SKILL.md currently asks the LLM to do, but in code:

1. Parse `--query` (JSON: `task_id`, `plan`, `workspace_dir`).
2. Resolve workspace_dir (`/tmp/uws-sandbox-{task_id}/` if absent).
3. `git clone https://github.com/caiobellizzi/test-workshop-sandbox.git {workspace_dir}` if `.git` missing.
4. `git -C {workspace_dir} checkout -b workshop/{task_id}`.
5. `subprocess.run(["python3", "aider_runner.py", "--task", plan["goal"], "--workspace-file", f"{workspace_dir}/README.md"])`.
6. Emit the Diff JSON envelope to stdout:
   ```json
   {"summary": "<first 500 chars of aider stdout>", "changes": [], "branch": "workshop/{task_id}", "workspace_dir": "{workspace_dir}"}
   ```
7. Support `--dry-run` (prints the hardcoded dry-run JSON, exits 0). Matches the current SKILL.md dry-run contract so bats tests keep passing.

`shell=False` throughout, matches `workshop_build.py` + `workshop_fix.py` style.

### B. `skills/coder-specialist/SKILL.md` (REWRITE behavior)

Reduce to two paths:
- `--dry-run` → `terminal python3 /opt/ultra-workshop/hermes-skills/workshop_coder.py --query "<query>" --dry-run`, forward stdout, end.
- Normal → `terminal python3 /opt/ultra-workshop/hermes-skills/workshop_coder.py --query "<query>"`, forward stdout verbatim, end.

The LLM no longer assembles JSON. Output schema doc stays for reference but is now produced by the script, not the model.

### C. `workshop/orchestrator.py::_extract_json` (harden)

Before brace-matching, strip ```json ... ``` and ``` ... ``` fenced blocks down to their inner content. Keeps `<think>` stripping. Add the fenced-block stripping as a single regex pass so the function stays ~10 lines.

```python
_FENCE_RE = re.compile(r"```(?:json)?\s*\n(.*?)\n```", re.DOTALL | re.IGNORECASE)
# inside _extract_json, after _THINK_RE.sub:
m = _FENCE_RE.search(text)
if m:
    text = m.group(1)
```

This recovers JSON from any specialist that wraps its envelope in markdown fences. Cheap insurance.

### D. Tests

- `tests/phase-04/test_extract_json.py` — extend (or create) with cases: bare JSON, ```json-fenced JSON, ``` plain-fenced JSON, JSON after `<think>` block, JSON inside both fence + think, no-JSON raises with skill_name in message.
- `tests/phase-04/coder-smoke.bats` — NEW. Two tests:
  1. `workshop_coder.py --dry-run` exits 0 and stdout contains `"branch":"workshop/dry-run"`.
  2. (skipped if workshop down) importability: `python3 -c 'import json; ...'` parses the dry-run stdout as a dict with keys `summary, changes, branch, workspace_dir`.
