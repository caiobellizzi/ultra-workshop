# 04-04 — Workshop specialist model matrix (NIM upgrade)

## Context

Brain just shipped a 5-tier LiteLLM proxy (`/opt/ultra-agents-brain/deploy/litellm/config.yaml`)
exposing NVIDIA NIM models alongside local Gemma and cloud fallbacks:

- `orchestrator` → NIM DeepSeek V4 Pro (thinking on) → failover GLM-5.1 → cloud-sonnet
- `research-worker` → NIM DeepSeek V4 Flash (1M ctx, thinking on) → Qwen 3.5 397B → cloud-sonnet
- `default-worker` → local Gemma → NIM Llama 3.3 70B → Mistral Large → cloud-groq
- `cheap-worker` & `private-worker` → local Gemma (local-only by contract)

This plan lifts reasoning quality on the planner, reviewer, and Aider architect by routing them
to NIM thinking-mode models, while keeping the high-token-volume Aider editor on `private-worker`
so V17 (≥80% local token volume) still holds. Cost ceiling: ~$2/build (grilled decision (c)).

L25 has been rewritten in PROJECT.md to reflect this matrix; V17 retains the 80% target with an
empirical-verification clause added.

## Decision matrix

| Specialist | Slot | Model alias | Rationale |
|---|---|---|---|
| triage-specialist | Hermes skill | `private-worker` (no change) | Classification, max-turns 3, tiny tokens; thinking adds latency without gain. |
| planner-specialist | Hermes skill | **`orchestrator`** | Reasoning-bound; NIM DeepSeek V4 Pro thinking-mode is the clear quality lever. |
| coder-specialist (orchestration) | Hermes skill | `private-worker` (no change) | Just orchestrates `aider_runner.py`. |
| coder/architect | Aider `--model` | **`orchestrator`** | Lift architect from Sonnet → NIM DeepSeek V4 Pro thinking. Sonnet remains as proxy failover. |
| coder/editor | Aider `--editor-model` | `private-worker` (no change) | Highest-volume slot; stays local to honor V17. Editor must NOT be thinking-mode (would break SEARCH/REPLACE). |
| reviewer-specialist | Hermes skill | **`research-worker`** | Diff-vs-plan judgment; 1M ctx swallows large diffs, Flash thinking is right-sized. |

## Risks acknowledged

- **NIM rate limit (40 RPM)**: interactive traffic nowhere near. Cron routes via `cloud-groq`. No mitigation.
- **DeepSeek thinking-mode latency**: 30–60s cold-start observed (obs 21811). 90s+ harness timeout already adopted. Acceptable.
- **`<think>` token leak into JSON**: mitigated by defensive strip. Falls back to brace-matching for non-leak case.
- **Per-home disk usage**: 3× config-only homes. Negligible.
- **First-build cost spike if NIM cold/throttled**: automatic proxy fallback to cloud-sonnet (architect) and cloud-groq (default-worker). Within $2 ceiling.
