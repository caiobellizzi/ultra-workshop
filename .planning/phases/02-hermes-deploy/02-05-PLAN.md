<!-- pending_hitl.db schema (Claude discretion) -->
```sql
CREATE TABLE IF NOT EXISTS pending_hitl (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    message_id TEXT,
    task_description TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status TEXT DEFAULT 'pending',  -- pending | approved | rejected | expired
    telegram_chat_id TEXT NOT NULL,
    telegram_message_id TEXT        -- set after inline keyboard sent
);
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /home/uws/.ultra-workshop/pending_hitl.db | SQLite file — uws-owned, stores session IDs and task descriptions; not a secret file but must not be world-writable |
| Telegram inline keyboard [Approve] | Only send-ability is gated — but the button itself can be tapped by anyone who has the message. Hermes must re-validate chat_id on callback. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-17 | Spoofing | Telegram inline keyboard callback (anyone with message can tap) | mitigate | startup-hitl-scan.py must re-validate that callback telegram_chat_id matches original chat_id=7113965359 before resuming flow |
| T-02-18 | Tampering | pending_hitl.db world-writable | mitigate | /home/uws/.ultra-workshop/ owned by uws:uws, mode 700; db file 0600 |
| T-02-19 | Denial of Service | Expired pending rows accumulating | accept | Phase 2 scope is single-user; a cleanup job for rows older than 7 days is a Phase 3 enhancement |
| T-02-20 | Repudiation | HITL approval not logged | mitigate | startup-hitl-scan.py writes approval timestamp and telegram_user_id to pending_hitl.db status field |
| T-02-SC | Tampering | npm/pip installs | accept | No new package installs in this plan; skill uses stdlib sqlite3 only |
