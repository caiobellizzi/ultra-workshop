# Plan 05-02: daily-research + nightly-tests Cron Skills + Telegram Alert Helper

## Goal
Ship the `telegram_alert.py` helper and two Hermes cron skills (`cron_daily_research.py`, `cron_nightly_tests.py`) plus the catch-up startup hook that re-runs missed schedules after a service restart.

## Context
`workshop/cost.py` exposes `check_circuit_breaker(mode="cron")` which raises `BudgetExhausted` or `BudgetWarning`. `hermes-skills/brain_http.py` exposes `call_agent(agent_id, message, user_id="workshop")` using multipart/form-data against `http://127.0.0.1:7000`. `workshop/repo_registry.py` exposes `list_active_repos()` returning `list[dict]` filtered to `entry["active"] == True`. The hook registration pattern follows `hermes-skills/startup-hitl-scan-hook/` — a directory with `HOOK.yaml` (declares `events: [gateway:startup]`) and `handler.py` (imports the skill module via importlib). Catch-up state files live under `/home/uws/.ultra-workshop/cron-state/`.

## Requirements
- REQ-ws-016 (daily-research cron routine)
- REQ-ws-017 (nightly-tests cron routine)
- REQ-ws-022 (catch-up startup hook)
- REQ-ws-023 (Telegram alert on cron failure)

## Tasks

### Task 1: `telegram_alert.py` — direct Bot API caller
**File:** `hermes-skills/telegram_alert.py` (new)
**What:** Create a standalone module with one public function:

```python
def send_alert(message: str, chat_id: str = "7113965359") -> None:
```

Implementation:
- Read `TELEGRAM_BOT_TOKEN` from `os.environ`. If missing, raise `RuntimeError("TELEGRAM_BOT_TOKEN not set")`.
- POST to `https://api.telegram.org/bot{token}/sendMessage` with `json={"chat_id": chat_id, "text": message}` using `httpx.post(url, json=..., timeout=10)`.
- Call `resp.raise_for_status()`. No retry logic — let the caller handle failures.
- No module-level state or global imports beyond `os` and `httpx`.

Do NOT use Brain's `notify` agent — research confirmed it is not registered in `app.py` and calls return 404.

**Acceptance:** `python -c "import telegram_alert; print(telegram_alert.send_alert.__doc__ or 'ok')"` exits 0 from the workshop venv (token check happens at call time, not import time).

### Task 2: `cron_daily_research.py` — daily research cron skill
**File:** `hermes-skills/cron_daily_research.py` (new)
**What:** Create a module with a `main()` function implementing the daily-research routine:

1. Import and call `sys.path.insert(0, "/opt/ultra-workshop")` then import `workshop.cost.check_circuit_breaker` and `telegram_alert.send_alert`. Call `check_circuit_breaker(mode="cron")` — catch `BudgetExhausted` and `BudgetWarning`, call `send_alert(f"[daily-research] skipped: {e}")`, return early.
2. Read `vault/_system/research-queue.md` from `VAULT_VPS_PATH` env var (fallback: `/srv/second-brain`). Find the first line matching the pattern `- [ ] ` that does NOT have `workshop.status: done` in its following frontmatter block. Extract the title text from that line.
3. Call `brain_http.call_agent("research", title)` to fetch a research synthesis. Extract the `content` field from the response dict.
4. Derive a filename: `vault/Inbox/{date}-research-{uuid4_short}.md` where `date` is `datetime.date.today().isoformat()` and `uuid4_short` is the first 8 chars of `str(uuid.uuid4())`.
5. Call `brain_http.call_agent("ingest", f"---\ntitle: {title}\nworkshop.created_by: daily-research\n---\n\n{content}")` to write the note to vault Inbox via Brain's ingest agent.
6. Mark the processed line `[x]` and append `workshop.status: done` as a comment on the next line in `research-queue.md`. Write back atomically using `pathlib.Path.write_text`.
7. Write `/home/uws/.ultra-workshop/cron-state/daily-research.last` with `datetime.date.today().isoformat()`. Create parent dirs with `mkdir -p`.
8. Call `send_alert(f"📑 Daily research: {title}. vault/Inbox/{filename}")`.
9. Wrap the entire body (steps 2–8) in `try/except Exception as e` — on failure call `send_alert(f"[daily-research] failed: {e}")` and re-raise.

Add `if __name__ == "__main__": main()` at the bottom.

**Acceptance:** `python -c "import cron_daily_research; print('ok')"` exits 0.

### Task 3: `cron_nightly_tests.py` — nightly test runner cron skill
**File:** `hermes-skills/cron_nightly_tests.py` (new)
**What:** Create a module with a `main()` function:

1. `check_circuit_breaker(mode="cron")` — same early-return pattern as daily-research.
2. `repos = [r for r in list_active_repos() if r.get("test_command", "").strip()]` — filter to repos with a non-empty `test_command` field. If none, write marker and return.
3. For each repo in `repos`:
   a. Clone to `/tmp/uws-test/{repo["full_name"].replace("/", "_")}` using `subprocess.run(["git", "clone", "--depth=1", f"https://github.com/{repo['full_name']}", clone_dir], capture_output=True, timeout=120)`. Skip repo and log if clone fails.
   b. Run `subprocess.run(repo["test_command"].split(), cwd=clone_dir, capture_output=True, timeout=300)`.
   c. Build a result dict: `{"repo": repo["full_name"], "exit_code": proc.returncode, "stdout": proc.stdout.decode()[-2000:], "stderr": proc.stderr.decode()[-2000:]}`.
   d. If `exit_code != 0`: call `brain_http.call_agent("ingest", f"---\ntitle: Test failure: {repo['full_name']}\nworkshop.suggested_action: fix-test-failure\nworkshop.created_by: nightly-tests\n---\n\n{result_summary}")`. Do NOT send a per-repo Telegram alert (REQ-ws-017 / D-10 — only infrastructure failures are alerted).
4. Write `/home/uws/.ultra-workshop/cron-state/nightly-tests.last` with today's ISO date.
5. Outer `try/except Exception as e`: `send_alert(f"[nightly-tests] infra failure: {e}")` then re-raise.

**Acceptance:** `python -c "import cron_nightly_tests; print('ok')"` exits 0.

### Task 4: Catch-up startup hook
**Files:**
- `hermes-skills/startup-cron-catchup-hook/HOOK.yaml` (new)
- `hermes-skills/startup-cron-catchup-hook/handler.py` (new)

**What:**

`HOOK.yaml`:
```yaml
name: startup-cron-catchup
description: "Re-runs missed daily-research and nightly-tests cron jobs after a service restart"
version: 1.0.0
author: ultra-workshop
events:
  - gateway:startup
```

`handler.py`: Load `cron_daily_research` and `cron_nightly_tests` via importlib from `/opt/ultra-workshop/hermes-skills/` (same pattern as `startup-hitl-scan-hook/handler.py` loading `startup-hitl-scan.py`). In the hook entry function:
1. Read `/home/uws/.ultra-workshop/cron-state/daily-research.last` — if the file does not exist or its content != today's ISO date AND current local hour >= 7: call `cron_daily_research.main()` in a `try/except` (log error, do not raise — other hooks must not be blocked).
2. Same check for `nightly-tests.last`, threshold hour >= 2.

Deploy location: hook is auto-discovered by Hermes from `~/.hermes/hooks/`. The install script (Plan 05-04) will symlink or copy this directory to `/home/uws/.hermes/hooks/startup-cron-catchup/`.

**Acceptance:** `cat hermes-skills/startup-cron-catchup-hook/HOOK.yaml | grep "gateway:startup"` returns the event line.
