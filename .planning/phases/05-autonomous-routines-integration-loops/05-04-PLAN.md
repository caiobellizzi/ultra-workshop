# Plan 05-04: Standard-Poll Cron + Integration Contract + Trust Symlink + Install Script

## Goal
Wire up the 4h/03:00 standard-poll Hermes cron skill, write the vault integration-contract doc, add the trust symlink step to the install script, extend the repo registry schema with `test_command`, and run the full V1–V24 verification matrix.

## Context
Hermes 0.14.0 cron jobs are registered via `cronjob(action="create", ...)` in a bootstrap skill. Standard-poll shares the same queue-dispatch logic as the fast-poll (Plan 05-03) but is invoked by Hermes on a schedule rather than running in an infinite loop. `workshop/repo_registry.py` already has `list_active_repos()` and a `seed_entry()` schema with no `test_command` field — this plan adds that field. The trust module is at `/opt/ultra-agents-brain/ultra_brain/trust.py`; the symlink target in ultra-workshop is `workshop/trust_shared.py`. `scripts/install.sh` already handles user creation, directory setup, Hermes install, and config symlinks — the trust symlink and new systemd unit install steps are appended there.

### Task 1: `cron_standard_poll.py` + Hermes cron registration bootstrap
**Files:**
- `hermes-skills/cron_standard_poll.py` (new)
- `hermes-skills/bootstrap_cron_jobs.py` (new)

**`cron_standard_poll.py`:**
Implement a `main()` function with the same dispatch logic as `cron_bug_scan_fastpoll._poll_once()` from Plan 05-03 — read `.workshop-queue.jsonl`, filter eligible entries, apply quiet-hours check, dispatch each verb. Key differences from fast-poll:
- No infinite loop, no PID file. `main()` runs once and returns.
- Same quiet-hours helper: `h = datetime.datetime.now().hour; return h >= 22 or h < 7`.
- Same verb dispatch: `post-to-telegram`, `link-orphans`, `build`, `fix`, unknown-warn-and-ack.
- Same `brain_http.mark_queue_entry_dispatched(entry["id"])` after each dispatch.
- Add `if __name__ == "__main__": main()` at bottom.

Import `check_circuit_breaker(mode="cron")` at the top of `main()` — catch `BudgetExhausted`/`BudgetWarning` and return early (no Telegram alert — standard-poll skipping budget is expected behavior, logged via `logging.warning` only).

**`bootstrap_cron_jobs.py`:**
A one-shot Hermes skill that registers all four cron jobs. Call the Hermes `cronjob` builtin (available in Hermes 0.14.0 skill context). This skill is run once during install by the install script via `hermes skill run bootstrap_cron_jobs`.

Register these four jobs (use `cronjob(action="create", ...)` for each):
```python
cronjob(action="create", id="daily-research",   schedule="0 7 * * *",   prompt="Run daily-research routine",             skills=["cron_daily_research"])
cronjob(action="create", id="nightly-tests",    schedule="0 2 * * *",   prompt="Run nightly-tests routine",              skills=["cron_nightly_tests"])
cronjob(action="create", id="standard-poll-4h", schedule="0 */4 * * *", prompt="Run standard queue poll",                skills=["cron_standard_poll"])
cronjob(action="create", id="nightly-rescan",   schedule="0 3 * * *",   prompt="Run nightly queue rescan",               skills=["cron_standard_poll"])
```

Set `HERMES_CRON_TIMEOUT=1800` note: this env var is set in `/etc/uws/env` by the install script (Step in Task 3), not here.

### Task 2: `workshop/repo_registry.py` — add `test_command` field + `list_repos_with_tests()`
**File:** `workshop/repo_registry.py` (modify)
**What:** Two changes:

1. In `seed_entry()`, add `"test_command": ""` to the returned dict (after `"last_used_at": None`). This makes the field part of the canonical schema so existing entries normalised through `normalize_registry` will include it.

2. Add a new helper function after `list_active_repos`:
```python
def list_repos_with_tests(path: str | Path | None = None) -> list[dict[str, Any]]:
    """Return active repos that have a non-empty test_command field."""
    return [r for r in list_active_repos(path) if r.get("test_command", "").strip()]
```

No other changes. Do not modify `normalize_registry` — it uses `{**defaults, **existing}` merging which will naturally fill missing `test_command` as `""` once `seed_entry` has it.

**Acceptance:** `python -c "from workshop.repo_registry import list_repos_with_tests; print('ok')"` exits 0.

**`vault/_system/integration-contract.md`** content:
```markdown
---
title: Workshop Integration Contract
workshop.created_by: install-script
---

# Workshop Integration Contract

This document defines the shared vocabulary between ultra-agents-brain (Brain)
and ultra-workshop (Workshop). Both sides MUST treat this as authoritative.

## Frontmatter Field Vocabulary

| Field | Owner | Written by | Valid values | Notes |
|-------|-------|------------|--------------|-------|
| `workshop.suggested_action` | Workshop | Brain ingest agent | `fix-test-failure`, `review`, `security-scan` | Suggestion only; requires human confirmation |
| `workshop.action` | Workshop | Brain daily-digest | `build`, `fix`, `post-to-telegram`, `link-orphans` | Confirmed verb for dispatch |
| `workshop.confirmed` | Workshop | Human via Telegram HITL | `true`, `false` | Must be `true` before fast-poll dispatches |
| `workshop.status` | Brain+Workshop | Either side | `pending`, `in-progress`, `done`, `failed` | Lifecycle state |
| `workshop.task_id` | Workshop | workshop_build / workshop_fix | UUID string | Correlates ledger entries |
| `workshop.dispatched` | Workshop | fast-poll / standard-poll | `true` | Set after ACK to Brain; prevents double-dispatch |
| `workshop.pr_url` | Workshop | workshop_push | GitHub PR URL | Written after PR creation |
| `workshop.created_by` | Brain | Brain ingest agent | `daily-research`, `nightly-tests`, `install-script` | Source traceability |

## Dispatch Flows

### Flow A: Build task
Brain daily-digest writes queue entry (`action: build`, `confirmed: false`) →
Telegram HITL (`confirmed: true`) →
fast-poll dispatches `workshop_build.py` →
ACK (`dispatched: true`) →
PR URL written back to vault.

### Flow B: Fix task
Brain daily-digest writes queue entry (`action: fix`, `confirmed: false`) →
Telegram HITL (`confirmed: true`) →
fast-poll dispatches `workshop_fix.py` →
ACK (`dispatched: true`).

### Flow D: Test failure (suggested, not auto-dispatched)
nightly-tests writes vault note (`workshop.suggested_action: fix-test-failure`) →
Brain daily-digest surfaces in digest →
Human reviews → promotes to Flow B if desired.

### Flow E: Post to Telegram (zero-HITL)
Brain daily-digest writes queue entry (`action: post-to-telegram`, `confirmed: true`) →
fast-poll sends Telegram message →
ACK (`dispatched: true`).

## Write Rules
- Only Brain writes `workshop.action` and `workshop.confirmed`.
- Only Workshop writes `workshop.dispatched`, `workshop.task_id`, `workshop.pr_url`.
- Either side may write `workshop.status`.
- `workshop.confirmed: true` is irrevocable once written.
```
