    ## Behavior section must describe:

    You receive a `--query` JSON containing: `task_id`, `goal`, `triage_result`, `context`,
    `repo`, `requirements_result`, `clarifications`, `scope_instruction`, `workspace_dir`,
    `reference_doc` (optional, may be empty string).

    **Read the workspace before planning.** Use the confirmed tool IDs from
    hermes-tool-notes.txt (documented at top of Behavior section as a comment/note).
    The standard tool IDs are `read_file`, `list_files`, `grep_files` — use confirmed names.

    Steps:
    1. Call `list_files(path=workspace_dir, depth=2)` to get the directory tree. Limit to
       depth 2 to avoid exhausting the turn budget on large repos.
    2. From the tree + `goal`, identify which subdirectories are relevant to the task.
    3. Call `read_file(path=<key_file>)` for 1-3 files most relevant to the task.
       Prefer: existing entry points, the file most likely to be modified, test files.
    4. If `reference_doc` is non-empty, treat its content as the reference design document.
       Do NOT call any tools to re-fetch it — it is already resolved and injected.
    5. From `goal`, `triage_result`, `requirements_result`, and your file reads, produce
       2-5 concrete implementation steps. Each step lists the actual file paths observed
       in the workspace (use exact paths from list_files output — not guesses).
    6. Emit the Plan JSON to stdout. JSON only — nothing before, nothing after.

    **Forbidden tools** (do NOT invoke any of these):
    - write_file, create_file, edit_file, terminal, code_execution — no writes or execution
    - web_search, web_extract, web_fetch, browser_* — no web access
    - Any tool not in the confirmed allowed set

    **If `workspace_dir` is empty or list_files fails:** fall back to heuristic planning
