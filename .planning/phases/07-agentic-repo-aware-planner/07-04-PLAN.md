## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| task goal string → _extract_doc_reference regex | User-supplied text; regex is read-only pattern match, no execution |
| workspace_dir path → clone target | Written by workshop code only; validated to be under /tmp/uws-workspace-* |
| resolved_doc_content → planner_query | Content from vault/Brain injected as reference; see T-07-02-03 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04-01 | Tampering | workspace_dir in state.json modified externally before resume | mitigate | On resume, clone_workspace checks `if not (workspace / ".git").exists()` — an injected path without a .git dir will trigger a fresh clone; .git presence does not grant write access beyond the workspace scope |
| T-07-04-02 | Elevation | workspace_dir path traversal (e.g. via state injection) | mitigate | workspace_dir is set by our code as f"/tmp/uws-workspace-{task_id}/" using task_id from secrets.token_hex(3) — not user-supplied; on resume, loaded from state.json (attacker would need write access to state.json which requires uws account) |
| T-07-04-03 | Information Disclosure | resolve_doc reads vault files before planner | mitigate | vault_path restricted to VAULT_VPS_PATH env var; doc_name validated in doc_resolver (Pitfall 5, traversal guard from Plan 02) |
| T-07-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages; gh CLI already installed (Phase 4 prerequisite) |
</threat_model>
