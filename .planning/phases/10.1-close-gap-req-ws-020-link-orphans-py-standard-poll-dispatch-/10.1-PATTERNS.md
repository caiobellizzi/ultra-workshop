**Why NOT `_run_skill()` for build/fix:**
- `_run_skill()` passes `input=json.dumps(entry)` to stdin (`cron_standard_poll.py` lines 83–96)
- `workshop_build.py` and `workshop_fix.py` call `argparse.ArgumentParser().parse_args()` — they read `sys.argv`, not stdin
- Piping JSON to stdin of an argparse script is a silent no-op; all entry data is lost

**`link-orphans` and `post-to-telegram` verbs:** already correctly use `_run_skill()` — these skills ARE stdin-JSON readers. Do not change those branches.

**`brain_http.mark_queue_entry_dispatched` call location:** remains at the bottom of `_dispatch_entry()`, after all verb branches — do not move it. (source: `cron_standard_poll.py` line 74)

```python
def main() -> None:
    """Read queue entry JSON from stdin; post entry["text"] to Telegram.

    Called when cron_standard_poll dispatches a post-to-telegram verb
    via _run_skill("telegram_alert", entry).
    """
    import json
    import sys
    raw = sys.stdin.read()
    try:
        entry = json.loads(raw)
    except json.JSONDecodeError as exc:
        raise SystemExit(f"telegram_alert main(): invalid JSON: {exc}") from exc
    send_alert(
        entry.get("text", "(no text)"),
        chat_id=entry.get("chat_id", DEFAULT_CHAT_ID),
    )


if __name__ == "__main__":
    main()
```
