<domain>
## Phase Boundary

Closes two live blockers surfaced by the v1.0 milestone audit, plus back-fills formal requirement traceability for 16 orphaned REQ-IDs from Phases 8 and 9.

**Blocker 1 — REQ-ws-020 (Flow B broken):** `link_orphans.py` does not exist. `cron_standard_poll.py` dispatches the `link-orphans` verb via `_run_skill("link_orphans", entry)` but the file is missing — standard-poll logs an error and skips. Brain→Workshop orphan-linking flow is non-functional.

**Blocker 2 — Standard-poll dispatch mismatch:** `cron_standard_poll.py` dispatches `build` and `fix` verbs by piping JSON to subprocess stdin, but `workshop_build.py` and `workshop_fix.py` parse via argparse — the entry JSON is silently dropped on every standard-poll dispatch. Also: `telegram_alert.py` has no `main()` so the `post-to-telegram` verb cannot be dispatched via subprocess at all.

**Traceability debt:** REQ-ws-035..042 (Phase 8: Specialist Quality Uplift) and REQ-ws-043..050 (Phase 9: Advanced Agent Architecture) were declared "to be minted during execution/planning" but were never added to REQUIREMENTS.md. 16 requirements have zero formal traceability.

**Out of scope:** Full vault-link updater (link_orphans.py writes to vault), HITL-confirm flow for orphan linking, fixing the worktree.py zero-caller gap beyond noting it in the minted requirements, any Phase 8/9 re-implementation.

</domain>

<decisions>
## Implementation Decisions

### link_orphans.py (REQ-ws-020 fix)
- **D-01:** Create `hermes-skills/link_orphans.py` as a **dispatch stub + Telegram post**: reads stdin JSON (the queue entry), extracts the orphan list from the entry payload itself (no extra brain_http calls), formats a plain-text message (`⚠️ Orphan vault notes:\n- note-1.md\n...`), and posts to Telegram via `telegram_alert.send_alert()`.
- **D-02:** No HITL prompt, no inline keyboard — simple one-way notification only.
- **D-03:** After posting, the script exits 0; `cron_standard_poll.py` then calls `brain_http.mark_queue_entry_dispatched(entry_id)` as it already does.
- **D-04:** The orphan list comes from the queue entry payload (field: `orphans` — list of vault paths). If the field is absent or empty, post a "no orphans in payload" fallback message and exit 0.

### Standard-poll dispatch interface fix
- **D-05:** Fix the mismatch by changing **`cron_standard_poll._dispatch_entry`** (not workshop_build/fix) to pass CLI flags for `build` and `fix` verbs. Map queue entry fields to argparse flags: `entry["repo"]` → `--repo`, `entry["task"]` → `--task-b64` (base64-encoded to handle spaces/special chars), `entry.get("chat_id", "7113965359")` → `--chat-id`. `workshop_build.py` and `workshop_fix.py` are **untouched**.
- **D-06:** Add a `main()` to **`telegram_alert.py`** that reads JSON from stdin and calls `send_alert()`. This closes the `post-to-telegram` subprocess dispatch gap and satisfies REQ-ws-021's standard-poll path. The existing `send_alert()` library function is unchanged; `main()` is a thin wrapper.

### REQ-ws-035..050 minting (traceability back-fill)
- **D-07:** Mint all 16 requirements at **acceptance-criteria level** — same format as existing REQUIREMENTS.md entries (name, description, acceptance criterion). Back-filled from what is actually implemented, not aspirational.
- **D-08:** REQ-ws-035..042 (Phase 8) → status: **Complete** (08-VERIFICATION.md shows `pass_with_caveats`; implementation is in place).
- **D-09:** REQ-ws-043..050 (Phase 9) → status: **Implemented** (code ships, no VERIFICATION.md written yet). Do NOT mark as Complete.
- **D-10:** The requirement covering git-worktree isolation (B5, Phase 9) is minted as Implemented with an explicit caveat: *"`worktree.py` created but not wired to production review wave — reviewers run via ThreadPoolExecutor only. Worktree integration is deferred."* Honest traceability — no false Complete status.

<code_context>
## Existing Code Insights

### Reusable Assets
- `telegram_alert.send_alert(message, chat_id)`: existing library function used by both fast-poll and cron_daily_research. link_orphans.py calls it directly (same pattern as fast-poll).
- `brain_http.mark_queue_entry_dispatched(entry_id)`: already called by cron_standard_poll after each dispatch; link_orphans.py exits before this call (the caller handles ACK).
- `cron_bug_scan_fastpoll.py`'s telegram dispatch pattern: model for link_orphans.py calling send_alert as a library.

### Established Patterns
- Standard-poll dispatches via `_run_skill(skill_name, entry)` which pipes JSON to stdin via `subprocess.run(..., input=json.dumps(entry))`. link_orphans.py MUST read from stdin (not argparse).
- workshop_build.py argparse accepts `--task-b64` for base64-encoded task strings — use this for standard-poll dispatch to avoid shell quoting issues.
- Phase 8 REQUIREMENTS.md format: `**REQ-ws-XXX** — [name]` then description block + `Acceptance:` line.

### Integration Points
- `cron_standard_poll._dispatch_entry` is the sole change point for the build/fix/post-to-telegram dispatch fix.
- `telegram_alert.py` new `main()` must NOT change the existing `send_alert()` signature — it's called by 3+ other files.
- REQUIREMENTS.md is append-only for new entries; existing entries for Phase 8/9 do not exist yet, so this is a pure addition in the correct position.

</code_context>
