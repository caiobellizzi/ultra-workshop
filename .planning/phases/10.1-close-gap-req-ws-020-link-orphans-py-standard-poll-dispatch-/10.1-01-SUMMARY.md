# Phase 10.1 Plan 01: Runtime Blocker Fixes Summary

## One-liner

Closed two live standard-poll runtime blockers: created the missing `link_orphans.py` stdin-JSON skill (REQ-ws-020) and fixed `cron_standard_poll._dispatch_entry` to dispatch `build`/`fix` via CLI flags instead of piping JSON to argparse-based skills; added `telegram_alert.main()` so `post-to-telegram` is subprocess-dispatchable (REQ-ws-021).

## What was built

- **`hermes-skills/link_orphans.py`** (new, 70 lines) — reads a queue entry from stdin, extracts `entry["orphans"]`, formats `⚠️ Orphan vault notes:\n- …`, and posts via `telegram_alert.send_alert()`. Empty/missing orphans → fallback message, still exits 0. Does not import `brain_http` and does not ACK the queue entry (the caller owns the ACK).
- **`hermes-skills/cron_standard_poll.py`** — added `import base64`; replaced the broken `build` and `fix` branches of `_dispatch_entry`. `build` → `subprocess.run([… "--repo", "--task-b64", "--chat-id"])`; `fix` → `subprocess.run([… "--issue-url", "--chat-id"])`. Both list-form (no `shell=True`), 1800s timeout, errors logged. `post-to-telegram` and `link-orphans` branches unchanged; ACK position unchanged.
- **`hermes-skills/telegram_alert.py`** — appended `main()` (stdin JSON → `send_alert(text, chat_id)`) + `__main__` guard. `send_alert()` body/signature untouched (3+ existing callers unaffected).
- **`tests/phase-10.1/`** — 12 unit tests across 3 files + `__init__.py`. Feature-detection `skipif` guards keep the suite collecting cleanly through the RED→GREEN progression.
