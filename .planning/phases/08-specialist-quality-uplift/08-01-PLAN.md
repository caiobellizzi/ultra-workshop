# Plan 08-01: Specialist Quality Uplift — Soul, Discipline & Context

## Objective

In-place uplift of the five specialist SKILL.md "souls" plus targeted Python changes to add: (1) a real build/test verification gate, (2) structured retry feedback, (3) institutional memory reads at planner and reviewer, and (4) fix two known inconsistencies in workshop-fix. Zero `workshop_build.py` flow restructure — all changes are SKILL.md edits and lightweight Python modifications within existing functions.

**Phase A from research session.** Derived from `/grill-me` against `obra/superpowers`, `paperclipai/paperclip`, and ecosystem research. Phased A-then-B; Phase B is Phase 9.

## Context & Motivation

The pipeline (triage → requirements → planner → coder(aider) → reviewer(2 retries) → HITL → push) works structurally but has three quality gaps:
1. **No execution verification** — reviewer does a static diff check only; broken diffs can ship.
2. **Blind retries** — reviewer failures aren't structured, so coder retries re-roll the same dice.
3. **Brain near write-only** — planner's brain-query is opt-in; reviewer never reads brain.

Two documented bugs also need fixing: `workshop-fix/SKILL.md` uses the old heredoc/`workshop_push.py` push pattern, and workshop-fix omits the requirements stage.

## Tasks

### Task 1 — Soul rewrites (SKILL.md discipline injection)
Rewrite all five specialist SKILL.md files to Superpowers-style mandatory-discipline specs:
- `skills/triage-specialist/SKILL.md` — tighten BUILD/FIX + complexity rules; add explicit "never guess" escalation.
- `skills/requirements-specialist/SKILL.md` — add goal-coherence check before HITL trigger; explicit "never choose interpretations for ambiguous domain language" rule retained and strengthened.
- `skills/planner-specialist/SKILL.md` — make brain-query standard (see Task 3); add forbidden-tool list as a mandatory SKILL section not prose.
- `skills/coder-specialist/SKILL.md` — add build/test-verify contract (see Task 2); task must include pass/fail in Diff JSON.
- `skills/reviewer-specialist/SKILL.md` — add two-pass structure, structured-failure output contract, and escalate-on-exhaustion behavior (see Task 2).

Verify: read each rewritten SKILL.md against the must_haves truths. No persona flavor introduced.

### Task 2 — Execute-and-verify + structured retry loop
**`hermes-skills/aider_runner.py`**: After applying the diff in the sandbox, run the repo's test/build command. Detect command from `package.json` scripts / `Makefile` / `pytest.ini` / `bats` in priority order; fallback = `echo no-test-command`. Capture stdout/stderr, exit code. Add `build_passed`, `test_passed`, `output_tail` (last 50 lines) to the returned Diff JSON object.

**`hermes-skills/workshop_reviewer.py`**: 
- Pass 1: evaluate `build_passed` + `test_passed` from Diff JSON. If either false → emit FAIL with `[{file, problem, required_fix}]` list immediately; skip pass 2.
- Pass 2 (only if pass 1 passes): existing static checks (spec compliance, secrets, syntax).
- All FAIL output must be `[{file, problem, required_fix}]` not prose.

**`hermes-skills/workshop_build.py`** (retry wiring only, no flow restructure):
- On reviewer FAIL, inject the `[{file, problem, required_fix}]` list into the next coder attempt as primary task context.
- After 2nd failed retry: exit with code 2 (reuse existing HITL machinery); human chooses accept-with-notes / more guidance / abort. Never emit a broken diff downstream.

Verify: `bats tests/phase-04/` stays green. New smoke tests assert structured-failure shape and exit-code-2 on exhaustion.

### Task 3 — Brain reads at planner + reviewer
**`hermes-skills/workshop_planner.py`**: Remove opt-in guard; always call `brain_http.call_agent("query", ...)` with query = `"repo conventions and relevant ADRs for {repo_full_name}"`. Inject result as context *after* behavior rules in the planner prompt (existing injection-mitigation position).

**`skills/reviewer-specialist/SKILL.md`**: Document that reviewer calls `brain-query` for `"project review rules and prior incident ADRs for {repo_full_name}"` before both review passes. Wire in `hermes-skills/workshop_reviewer.py` if brain-query is a subprocess call.

Verify: planner and reviewer log entries show brain-query calls in a test run.

### Task 4 — Fix workshop-fix inconsistencies
**`skills/workshop-fix/SKILL.md`**:
- Replace the heredoc/`workshop_push.py` push path with `workshop_continue.py` (matching workshop-build's pattern).
- Add `requirements-specialist` stage to the documented pipeline flow.

Verify: `diff skills/workshop-fix/SKILL.md skills/workshop-build/SKILL.md` shows no push-path divergence.

### Task 5 — Validation + deploy
1. `bats tests/phase-04/` — existing suite green.
2. Add/extend smoke test for: structured-failure `{file,problem,required_fix}` contract; exit-code-2 on 2nd-retry-exhaustion.
3. One real end-to-end run against `new-test` sandbox repo: confirm build/test-verify + structured retry + planner/reviewer brain-read fire in logs.
4. Manual HITL gate check via Telegram: clarification path + new escalation gate.
5. Deploy: copy changed SKILL.md + .py to `ultra-workshop/hermes-skills/` and uws `~/.hermes/skills/`, restart gateway, update `deploy/phase-04-manifest.txt` and `README.md` in same commit.
