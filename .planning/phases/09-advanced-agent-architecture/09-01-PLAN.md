## Objective

Restructure the workshop pipeline into a richer team model: adds a conception/brainstorm front-end, Paperclip-style agent accountability (personas + token budgets + immutable audit log), a parallel six-scope review wave replacing the single reviewer, and AgentTool/SkillTool discipline for cost control.

**Phase B from research session.** Derived from `/grill-me` against `obra/superpowers`, `paperclipai/paperclip`, `VILA-Lab/Dive-into-Claude-Code`, `GetBindu/awesome-claude-code-and-skills`. Phase A (Phase 8) must ship first.

## Architectural Changes (relative to Phase 8 baseline)

### B1 — Conception / Brainstorm stage (new pre-triage role)
A Socratic problem-space exploration loop before triage. The agent explores: Is this the right thing to build? What are the alternatives? Does it conflict with known decisions? Multi-turn HITL (conversational), not fire-and-forget. Superpowers brainstorm-gate pattern. Outputs a scoped goal statement that feeds triage.

Pipeline becomes: **brainstorm → triage → requirements → planner → coder → review-wave → HITL → push**

Spec-level decisions needed before planning:
- Trigger: explicit `/brainstorm <task>` vs. always-on flag on `/build`
- Turn limit (suggested: 3-5 exchanges max before auto-proceeding to triage)
- Exit criteria: "goal statement is unambiguous" vs. "user explicitly approves"

### B2 — Agent personas + token budgets (Paperclip employee model)
Each specialist gets:
- A job description (role title, responsibilities, reporting line) — richer persona framing for judgment-heavy roles (requirements, planner).
- A monthly token budget tracked in `brain/_system/cost-ledger.md` per agent role.
- Auto-pause at 100% monthly budget utilization with Telegram alert; human resumes.

Implementation: extend `hermes-skills/brain_http.py` budget-check + `workshop/cost.py` role-level tracking.

### B3 — Immutable per-ticket audit log
Every instruction, tool call, and decision appended to an append-only log keyed by `task_id`. Written to brain via `brain_http.call_agent("ingest", ...)` after each pipeline event. Enables full post-mortem of any run. Format: `vault/_system/workshop-audit/{task_id}.jsonl`.

### B4 — Parallel six-scope review wave
Replace single `reviewer-specialist` with six non-overlapping AgentTool-isolated subagents:
1. **correctness-reviewer** — does the diff implement the plan correctly?
2. **security-reviewer** — OWASP, secrets, auth/authz, input validation
3. **performance-reviewer** — N+1 queries, unnecessary allocations, hot paths
4. **test-coverage-reviewer** — missing branches, edge cases, integration gaps
5. **docs-reviewer** — README, docstrings, CHANGELOG accuracy
6. **config-reviewer** — deploy, env vars, feature flags, secrets handling

Each returns a bounded `[{file, problem, required_fix, severity}]` report. A **merge-agent** deduplicates and auto-fixes `severity: low` items; `severity: high` blocks the HITL gate.

Orchestration: all six run in parallel (`wave: 2`); merge-agent is `wave: 3`.

### B5 — git-worktree parallelism
Each file-editing agent gets a dedicated git worktree. Lock-based coordination (per-file `{file}.lock`). Enables safe concurrent agents without merge conflicts. Required for B4's parallel review wave to co-exist with coder's sandbox.

### B6 — AgentTool vs SkillTool discipline
Apply VILA-Lab's 7× token cost finding:
- Code agents (coder, six reviewers, merge-agent) → AgentTool (isolated context)
- Lightweight gates (triage, requirements, planner verification) → SkillTool (shared context)
Document in `hermes-config/agent-isolation-policy.md`.

### B7 — requirements-specialist reads brain
Requirements queries brain for `"prior clarifications for {repo_full_name}"` before triggering HITL. Reduces unnecessary human interruptions when the same ambiguity was resolved on a prior task.
